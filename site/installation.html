Installer

ultra11y s’installe dans votre agent de code. Un agent de code est un assistant IA qui lit et modifie le code de votre dépôt. Il faut Node.js 22.18 ou plus récent (nodejs.org, version LTS).

Dans votre agent

Commandes d’installation selon l’agent utilisé
AgentInstallation
Claude Code/plugin marketplace add SocialGouv/ultra11y puis /plugin install ultra11y@ultra11y, dans la conversation
Codex CLIcodex plugin marketplace add SocialGouv/ultra11y puis codex plugin add ultra11y@ultra11y, dans le terminal
OpenCode 1.x et 2.xnpx ultra11y install --opencode
Autres agentsnpx skills add SocialGouv/ultra11y : les deux skills seules, sans relecture automatique

Sur Codex, la relecture automatique passe par les hooks, qu’il faut activer : npx ultra11y install --codex ajoute hooks = true sous [features] dans ~/.codex/config.toml. Pour vérifier ce qui est réellement branché, dans chaque agent :

npx ultra11y status

Ensuite, demandez simplement à l’agent : « audite ce site selon le RGAA ». Le détail par agent est dans references/harnesses.md.

Deux skills, un même moteur

Une skill est un mode d’emploi que l’agent charge quand la tâche s’y prête. Les deux embarquent le même moteur, sans installation supplémentaire.

La relecture avant chaque commit

Installé comme extension, ultra11y ajoute un hook : quand l’agent lance git commit, git push ou gh pr create, le hook audite le diff. S’il trouve un défaut, il bloque la commande une seule fois et transmet les constats à l’agent, qui lance review-a11y. Une nouvelle tentative passe toujours.

  • Le hook ne force pas l’agent : il bloque et explique, c’est l’agent qui agit.
  • Sur un agent sans hooks (Cursor, Zed, Gemini CLI…), rien n’est automatique : npx ultra11y install --agents-md présente le moteur à l’agent dans AGENTS.md, et npx ultra11y init --hook installe un hook git classique, qui bloque le commit lui-même.
  • Pour le couper : SKIP_A11Y=1 pour une commande, ULTRA11Y_HOOK=off pour une session, "hook": { "failOn": "off" } dans .ultra11yrc.json pour le dépôt.

La bibliothèque de tests

Pour capturer les pages depuis vos tests Playwright ou Cypress, ajoutez ultra11y aux dépendances de développement du projet :

npm i -D ultra11y

L’usage est décrit sur la page Audit.

Ça ne marche pas ?

« npx » n’est pas reconnu, ou command not found
Node.js n’est pas installé, ou le terminal a été ouvert avant son installation. Ouvrez un nouveau terminal et tapez node --version.
Windows : « l’exécution de scripts est désactivée sur ce système »
Tapez npx.cmd à la place de npx, par exemple npx.cmd ultra11y status.
Node.js est trop ancien
Un avertissement EBADENGINE s’affiche : installez la version LTS depuis nodejs.org.
La relecture ne se déclenche pas
npx ultra11y status dit quels agents ont le hook. Sur Codex, vérifiez hooks = true sous [features].

Un autre problème ? Décrivez-le, avec la commande tapée et le message affiché, dans une demande sur GitHub.
