ultra11y : l’audit d’accessibilité qui dit ce qu’il ne sait pas vérifier

ultra11y vérifie qu’un site respecte le RGAA, la norme française d’accessibilité numérique, et les WCAG 2.2 niveau AA, la norme internationale dont il découle. Il fait le travail mécanique. Il dit clairement ce qu’il ne sait pas vérifier.

  • 106 critèresdans le RGAA 4.1.2, vérifiés par 258 tests officiels
  • 30 / 258tests qu’une règle automatique peut trancher ; tous les autres demandent un jugement
  • 94vérifications automatiques sur le code source, sans navigateur
  • 0fausse alerte non expliquée sur 401 exemples corrects du corpus officiel du W3C

Essayer en une commande

Il faut Node.js 22.18 ou plus récent. Rien d’autre à installer : le moteur tient dans un seul fichier, sans dépendance.

npx ultra11y audit src --standard rgaa

La commande lit les fichiers HTML, JSX, TSX, Vue, Svelte ou Astro du dossier src. Elle affiche les non-conformités trouvées, classées par critère RGAA, avec le fichier et la ligne. Pour un rapport daté :

npx ultra11y audit src --standard rgaa --out audits --json
npx ultra11y report --in audits/audit-latest.json --standard rgaa --out audits

Le rapport liste aussi tout ce qui reste « à évaluer ». C’est normal : un outil automatique ne tranche qu’une petite partie du RGAA. La suite se fait avec un agent IA (voir l’audit complet).

Dans un agent de code

Un agent de code est un assistant IA qui écrit et modifie du code dans votre dépôt (Claude Code, Codex, OpenCode…). Installé comme extension, ultra11y relit vos changements avant chaque commit, push ou pull request, sans que vous ayez à le demander.

Une skill est un mode d’emploi que l’agent charge quand la tâche s’y prête. Le dépôt en fournit deux : review-a11y pour relire un changement, ultra11y pour l’audit complet. Le détail est sur la page Intégration.

Ce que c’est

Un moteur déterministe

Déterministe veut dire : même code, même résultat, à chaque fois. Le moteur lit le code source et applique 94 vérifications : image sans alt, champ sans étiquette, page sans langue, tableau sans en-têtes… Il fonctionne hors ligne, sans clé ni compte.

Un passage dans le navigateur

La commande scan ouvre la page dans un vrai navigateur. Elle y lance axe-core, une bibliothèque de tests d’accessibilité reconnue, et mesure ce que le code seul ne dit pas : contraste réel, focus visible, zoom à 200 %, affichage sur petit écran.

Un agent IA qui juge, sous contrôle

La plupart des tests RGAA demandent un jugement : cette alternative décrit-elle l’image ? ce lien est-il explicite ? L’agent IA tranche à partir des preuves collectées par le moteur. Chaque verdict doit citer ce qu’il a lu.

Des garde-fous

Les commandes check et verify refusent un verdict sans preuve, un critère inventé ou un « conforme » prononcé sur des éléments incomplets. Une non-conformité doit toujours pointer vers un élément réel du code.

Au bout : un rapport RGAA daté, une grille critère par critère et page par page, un backlog de corrections et, si vous le voulez, des tickets GitHub, GitLab ou Jira.

Ce que ce n’est pas

  • Pas une certification. Un rapport ultra11y aide à préparer un audit RGAA. Il ne remplace pas une déclaration d’accessibilité signée par un auditeur.
  • Pas un « score » d’accessibilité. Le taux affiché porte sur les critères décidés. Tout ce qui n’a pas été vérifié reste « à évaluer », jamais « conforme » par défaut.
  • Pas infaillible côté IA. Les garde-fous vérifient que l’IA cite ses preuves. Ils ne prouvent pas qu’elle juge juste. Ce point est détaillé sur la page Fiabilité.
  • Pas Lighthouse. L’onglet accessibilité de Lighthouse exécute une partie des règles d’axe-core. ultra11y utilise axe-core directement, et ajoute ses propres règles.
